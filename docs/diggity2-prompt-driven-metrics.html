Métricas configuradas
desde archivos de prompt

Una nueva capa de diseño que desacopla las reglas de evaluación periodística del código Python — los thresholds, criterios y firmas LLM viven en archivos versionables que cualquier integrante del equipo puede editar sin tocar el backend.

🤖 LLM · DSPy + OpenRouter 📊 NLP · Stanford Stanza ⚙️ FastAPI REST 🔌 Chrome Extension desconfio.org
Motivación

¿Qué problema resuelve?

😰

Antes

  • Thresholds hardcodeados en metrics.py
  • Prompt del LLM en una cadena de texto dentro del código
  • Cambiar un umbral requería PR + revisión de código
  • Difícil auditar por periodistas sin contexto técnico
✨

Ahora

  • Cada métrica tiene su .txt + .json en prompts/
  • El prompt es el artefacto versionado (optimizable con DSPy)
  • Thresholds en JSON → editables sin tocar Python
  • Código lee la config en runtime → zero rebuild
Arquitectura

Cómo funciona

El loader prompt_loader.py une ambos archivos y construye la firma DSPy en runtime.

📄 prompt-X.txt
Instrucciones LLM
→
🗂 prompt-X.json
Inputs / Outputs / Thresholds
→
⚙️ prompt_loader
load_dspy_signature()
load_thresholds()
→
🐍 metrics.py
Cálculo en runtime
→
🌐 REST API
JSON response
💡 Zero rebuild — modificar un threshold o el texto del prompt toma efecto en la próxima request sin reiniciar el servidor.

El .txt es optimizable por DSPy.
El .json declara el schema y thresholds. 
// prompt-word-count.json
{
  "name": "WordCountEvaluator",
  "inputs": {
    "total_words": {
      "type": "integer",
      "description": "Total words"
    }
  },
  "thresholds": {
    "comprehensive": { "min_words": 500, "flag": 1,  "score": 0.9 },
    "adequate":      { "min_words": 300, "flag": 0,  "score": 0.6 },
    "too_brief":     { "min_words": 0,   "flag": -1, "score": 0.3 }
  }
}
Métricas implementadas

5 métricas · 2 modos de evaluación

🔤
LLM · DSPy

Adjetivos Calificativos

Filtra adjetivos subjetivos via OpenRouter. Mide ratio sobre total de palabras.

≤ 5 % → excelente (0.9)
≤ 10 % → moderado (0.6)
> 10 % → sesgado (0.3)
📝
Estadística · Stanza

Conteo de Palabras

Longitud total tokenizada. Mayor extensión correlaciona con cobertura profunda.

≥ 500 → completo (0.9)
≥ 300 → adecuado (0.6)
< 300 → muy breve (0.3)
📐
Estadística · Stanza

Complejidad Oracional

Promedio de palabras por oración. Indica legibilidad y calidad de redacción.

15–25 pal. → óptimo (0.9)
10–15 / 25–35 → aceptable (0.6)
<10 / >35 → problema (0.3)
⏱️
Estadística · Stanza

Tiempo Verbal

Ratio verbos en pasado / total verbos. Distingue reporting de opinión.

40–70 % → estilo noticioso (0.85)
20–40 % / 70–85 % → aceptable (0.60)
<20 % / >85 % → inusual (0.30)
🔗
LLM · DSPy

Relación Titular–Contenido

LLM clasifica si el titular coincide, contradice o solo coincide en parte con el cuerpo.

COINCIDE → (1.0)
COINCIDE_EN_PARTE → (0.5)
CONTRADICE → (0.0)
Métrica en profundidad · LLM

Adjetivos Calificativos

📄 prompt-adjectives.txt

«Filter and count qualitative/calificative adjectives from a list.

A qualitative adjective expresses an opinion, judgment, or subjective evaluation (e.g. "terrible", "amazing") as opposed to relational adjectives that describe objective properties (e.g. "presidential", "monthly").»

Pipeline

1. Stanza extrae ADJ via POS 2. LLM filtra solo los calificativos 3. ratio = qualitative / total_words 4. Threshold desde JSON → flag + score
Failover: si OpenRouter no responde, se usan todos los adjetivos sin filtrar. 
// Llamada en metrics.py
QualitativeAdjectiveFilter = load_dspy_signature(
  "adjectives"
)

with dspy.context(lm=lm):
    result = dspy.ChainOfThought(
        QualitativeAdjectiveFilter
    )(adjectives="...lista...")

# Ejemplo input/output
# in:  "hermosa, política, económico, terrible"
# out: count = "2"  (hermosa + terrible)

th = load_thresholds("adjectives")
# th["excellent"]["max_ratio"] → 0.05
# th["moderate"]["max_ratio"]  → 0.10
Input: adjectives (string) Output: count (int)
Métrica en profundidad · LLM

Relación Titular–Contenido

📄 prompt-relación-titular-contenido.txt

«Clasifica el titular en EXACTAMENTE UNA de estas tres categorías mutuamente excluyentes:

CONTRADICE — el titular afirma algo que el cuerpo desmiente.
COINCIDE — refleja fielmente la información principal.
COINCIDE EN PARTE — contiene elementos del cuerpo pero exagera u omite contexto.»

Scoring

COINCIDE → flag 1, score 1.0
COINCIDE_EN_PARTE → flag 0, score 0.5
CONTRADICE → flag -1, score 0.0
// prompt-relación-titular-contenido.json
{
  "name": "TitularContenidoEvaluator",
  "inputs": {
    "titular":      { "type": "string" },
    "texto_noticia": { "type": "string" }
  },
  "outputs": {
    "clasificacion": { "type": "string" },
    "justificacion": { "type": "string" }
  },
  "thresholds": {
    "COINCIDE":         {"flag": 1,  "score": 1.0},
    "COINCIDE_EN_PARTE":{"flag": 0,  "score": 0.5},
    "CONTRADICE":       {"flag": -1, "score": 0.0}
  }
}
Implementación

prompt_loader.py — API pública

from mediaparty_trust_api.services.prompt_loader import (
    load_dspy_signature,
    load_thresholds,
    list_prompts,
    validate_prompts,
)

# Construye dspy.Signature dinámica desde archivos
Filter = load_dspy_signature("adjectives")

# Carga thresholds como dict
th = load_thresholds("word-count")
# → {"comprehensive": {"min_words": 500, ...}}

# Listado de prompts disponibles
prompts = list_prompts()

# Validación estructural (CI-ready)
result = validate_prompts()
# → {"valid": [...], "errors": [...], "total": N}

Funciones expuestas

load_dspy_signature(name)

Construye dspy.Signature subclass dinámica a partir de .txt + .json.

load_thresholds(name)

Retorna el dict de thresholds del JSON sin cargar todo el schema.

list_prompts()

Enumera todos los prompts con flags has_thresholds, has_llm_signature.

validate_prompts()

Valida JSON + .txt + tipos soportados + build DSPy. Ideal en CI.

API Response

Output unificado por métrica

Cada métrica devuelve el mismo schema Metric:

{
  "id":            0,
  "criteria_name": "Qualitative Adjectives",
  "explanation":   "The ratio (3.2%) is excellent,
                  indicating objective writing.",
  "flag":          1,
  "score":         0.9
}

Campos

flag = 1 → positivo / cumple el criterio
flag = 0 → neutro / aceptable
flag = -1 → negativo / alerta
score → [0.0 – 1.0] confianza cuantitativa

Endpoint: POST /api/v1/articles/analyze

Beneficios

¿Por qué importa este diseño?

📝

Editabilidad sin código

Periodistas y editores pueden ajustar thresholds y texto del prompt editando un JSON. No hace falta saber Python.

🔄

Versionado independiente

Los archivos de prompt tienen su propio historial en git. Un cambio de criterio es un commit con diff legible.

🤖

Optimización con DSPy

El .txt es el artefacto que DSPy puede optimizar automáticamente mediante few-shot o bootstrap.

🧪

CI-ready

validate_prompts() verifica la integridad estructural de todos los archivos en cada push.

🔌

Extensibilidad

Agregar una nueva métrica es crear un par .txt + .json y llamar al loader. Sin modificar código existente.

🛡️

Failover robusto

Si el LLM no responde, las métricas estadísticas siguen funcionando. Degradación grácil por diseño.
